# video-hook

把正文中值得继续追问的结果提前展示。先理解整片，再选片段；Python 负责可靠剪辑，Agent 负责判断主旨、惊讶点和连贯性。

## 入口与边界

- 输入：已剪好的本地视频 + **同一时间线**的 SRT。确认字幕是成片时间线，不是原始口播时间线；抽查开头、中间、结尾的字幕与画面/语音位置。
- 保留已有画面、声音、烘焙字幕；不重新 ASR、不自动配音、不重做字幕。
- 仅写新的版本目录，源视频/SRT 和旧预览不覆盖。
- 默认做 1–3 个值得看的候选，也允许结论“没有合适钩子”。不按数量凑结果。
- 10 秒只是参考。先保全对比，再删冗余。保留原意、因果和操作顺序；禁止把多步工作伪装成一步或变速冒充效率。
- 所有脚本均通过当前 Skill 目录下 `scripts/run.py` 启动；它自动解析软链接到唯一仓库的 `.venv`。若环境缺失，按仓库 README 安装，不能另建三套运行环境。
- 使用本机工具，不把媒体上传第三方。Agent 接收到的字幕/图片遵循用户所用 Agent 的数据规则。

## 工作流程

1. **建立素材证据**：运行 `prepare`。读取整份 `transcript.json`；`windows.json` 是便于阅读的分窗，不是排名。查看全片 `frames/` 抽样，必要时补看安静的操作镜头，不能只靠字幕挑段。
2. **先写主旨**：用一句话概括正文兑现的核心价值。候选必须说明与主旨/产品的直接关系；局部反差不能抵消跑题。具体结果/可见的前后差异优先，作者的一句总结不算惊讶证据。
3. **核对候选**：结合原片逐段检查前态→操作→结果，精确取帧/播放相关片段；说明观众因此想知道什么、正文在哪兑现。不编造“已看”“已听”。读 [selection.md](references/selection.md)。
4. **写计划**：复制生成的 `plan.template.json` 为新的计划，补齐主旨、证据、保持原意的说明、按原片顺序排列的 `segments`。以输出帧率对齐切点。长段可删解释/重复/铺垫，保留必要条件。读 [cli.md](references/cli.md)。
5. **预览与技术检查**：运行 `render`。SRT 是语义线索，不是声音边界；从真实音轨检查是否截字、带入下一句、接缝突兀。查看实际对比是否可见，核对黑屏和声音渐隐。默认尾部 0.4 秒渐黑 + 0.2 秒黑屏，可依帧率微调。当前保留的 A 版沿用此默认值；直接切黑、无黑场、深灰场暂不采用。给用户比较转场时，在钩子后接一段从已确认正文起点开始的原片，避免只看孤立尾帧。已有配乐保持，v0.1 不自动追加音效。
6. **给用户复核**：提供本地视频预览、所选原文/删掉的内容、选段理由和待确认点。不能把全解码通过说成人工试听通过。记下用户实际反馈并精修；不要擅自改写口播、合成新结论。
7. **确认后前置**：用户认可钩子且同意前置时才 `approve` + `prepend`。先检查原片是否已有钩子。若已有，必须确认保留还是替换，并记录正文起点；默认未知时脚本会拒绝确认。未授权删除原片开头，不能自行填写替换起点。
8. **交付**：新 MP4、重映射 SRT、JSON 计划/命令/验证记录。清楚报告输出分辨率、是否重新编码、技术验证与用户听感范围。没有留存数据不能宣称提升完播率。

## 调用示例

将 `SKILL_DIR` 替换为本次加载的 Skill 绝对目录（允许软链接路径）；不要依赖当前工作目录。

```bash
python3 "$SKILL_DIR/scripts/run.py" prepare --video /absolute/final.mp4 --srt /absolute/final.srt --out /absolute/hook-work-v1
python3 "$SKILL_DIR/scripts/run.py" render --plan /absolute/plan.json --out /absolute/hook-preview-v1 --max-side 1920
```

`--max-side 0` 保持原始尺寸。前置成片沿用获批预览的分辨率；要交付 4K，必须先渲染并复核原尺寸钩子。

## 已认可的校准案例

读 [cases.md](references/cases.md)。明基：完整对比 22 秒→忠于原意的段内精剪 14.1 秒，用户确认衔接自然。鱼灯：9.13 秒，修正带入下一句、渐黑和黑屏。两例是人工反馈基准，不是留存效果实验，也不是自动全流程验收。
